Workflow 2.0: terminal-only code review

Do the whole code review loop without leaving the terminal emulator. The phases are tool-agnostic on purpose; tools get swapped in and out until the flow feels right.

Companion to README.md in this directory. Last updated 2026-10-01.

Phases

Each phase has a clear exit condition so I can tell which tool is doing which job.

  1. 0 · layerWorkspaceA pane exists for the repo
  2. 1TriageI have chosen a PR
  3. 2FetchBranch checked out or in a worktree
  4. 3DiffI know what changed
  5. 4ExploreI know why it changed
  6. 5ReviewReview submitted
  7. 6Follow upPR merged or closed, branch gone

Diff and Explore loop with each other. Review and Follow up loop until merge.

#PhaseWhat happens hereDone when
0WorkspaceThe layer everything runs in: terminal emulator plus a multiplexer that holds a pane per repo or task and survives detach. Not really a step, it is always there.A pane exists for the repo I am reviewing
1TriageSee what needs my attention: PRs assigned to me, review requests, CI status, notifications. Pick one.I have chosen a PR
2FetchGet the PR branch onto my machine so local tools can see it.PR branch is checked out, or a worktree exists for it
3DiffRead the change itself: changed files, hunks, commits.I understand what changed
4ExploreLeave the diff and read the surrounding code on the PR branch: callers, tests, history, blame. Run tests if needed.I understand why it changed and what it touches
5ReviewLeave line comments and suggestions, write the summary, approve / request changes / comment.Review is submitted on GitHub
6Follow upWatch for replies, re-review after new pushes, merge, clean up the local branch.PR is merged or closed and the branch is gone locally

Triage: dashboard TUIs

gh dash alternatives

gh dash current
Configurable sections, gh extension.
ghdash
Rust/ratatui. Orgs, all open PRs, review inbox, search, auto-refresh. More "inbox across repos" than configurable sections.
prtop
Small live monitor of PRs I author or review, with notifications. Also a Follow up candidate.
gitpane
Multi-repo workspace TUI, local status plus PRs/issues. Complements lazygit.
github-pr-attention
Focused "PRs that need me" inbox. Comment, approve, request changes, squash merge from the list.

Review: standalone TUIs

Do Diff and Review in one tool, outside Neovim, no checkout needed

gh-prism try first
gh extension. Description, commits, files, conversation, highlighted diffs, inline comments and suggestions, submit, merge.
gh extension install kawarimidoll/gh-prism then gh prism 123
tuicr
Vim motions, GitHub-style continuous diff, line and range comments, submits to GitHub or GitLab. Also works on local diffs.
prtui
Modal, vim-ish, GitHub PRs and GitLab MRs. Can review local uncommitted diffs.
prr
Writes the PR to a review file I edit in Neovim, then submits. Pairs well with worktrees.

Review: Neovim plugins

octo.nvim alternatives

octo.nvim current
Kitchen sink: issues, PRs, discussions, actions.
gh-review.nvim try
Review only: side-by-side diffs, threads, suggestions, submit. Designed to sit next to gh dash, listing is a non-goal. Most direct "keep dash, better reviewer than octo" swap.
ghlite.nvim
Lighter octo-ish review, can review without checkout.
github-pr-reviewer.nvim
Review in real buffers so LSP and gd keep working. Covers the Explore gap.
gh.nvim
Older full review UI built on litee.nvim.
snacks.nvim
Picker for open PRs and issues, not a review UI. Triage only.
diffview.nvim + gitsigns
Not GitHub-aware. Checkout or worktree, set gitsigns base to the target branch, review as normal code, comment with something else.

Open questions

  • Does gh dash or octo.nvim own triage? Having both is one step too many. Flow B keeps dash, Flow C drops it.
  • Worktree per PR vs checkout in place. Worktrees keep my main working tree clean but need a new herdr pane each time. Flow D.
  • What tells me a PR I reviewed got a new push, without opening a browser? prtop and gh-notify are the candidates.
  • Review TUIs (gh-prism, tuicr) skip Fetch entirely. Is losing Explore (no LSP, no gd) acceptable for small PRs?
